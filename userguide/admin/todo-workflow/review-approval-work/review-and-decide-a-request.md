# review and decide a request

## review and decide a request

use this procedure for an actionable Todo queue. the category articles below add the checks that are unique to each type of request.

### before you decide

confirm the company, employee or batch, covered dates or period, current status, source record, approver level, warnings, and downstream effect. when an action can affect time, pay, benefits, tax, documents, or payment, open the corresponding source detail before approving.

### approve or reject

1. open the correct Todo category.
2. find and open the request.
3. compare the request with its source record and relevant settings.
4. review the approver trail and confirm that the request is at your level.
5. select the applicable row or rows.
6. choose **Approve selected**, **Reject selected**, or the corresponding supported action.
7. review the selected-item count in the confirmation.
8. select **Download a copy** when the queue offers it and you need a decision-time record.
9. enter a password, remarks, or another confirmation value only when the selected action asks for it.
10. confirm the decision, then reload or revisit the source record to verify the result.

when several approvers are configured at the same level, any authorized approver at that current level can complete the level. configured levels proceed in order. approval is final only after the final configured level completes.

{% hint style="warning" %}
**warning:** bulk actions apply the selected decision to several records. verify the selection count, employee or batch scope, and any download option before confirming.
{% endhint %}

\## understand what happens next

an approval either advances the request to the next level or completes the source-module approval. a rejection records the rejected outcome defined by that module. correction and resubmission happen in the source module; rejecting a request does not automatically create a corrected replacement.

some attendance requests tied to a closed payroll cannot be approved. where the queue provides a cleanup action for those requests, review the affected records before rejecting them in bulk.
