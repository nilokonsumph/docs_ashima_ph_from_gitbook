# start here: review employee time

## start here: review employee time

use **Hours** to review captured time against the employee's assigned shift, correct supported records, resolve attendance exceptions, manage overtime and rest-day work, and verify the inputs used by payroll.

### how does Hours fit into the timekeeping flow?

1. **Shifts** defines the expected schedule, required punches, breaks, rest days, and cross-date context.
2. employees record time through an enabled clock-in method.
3. **Hours** matches the captured logs with the applicable shift and calculates attendance results.
4. employees or administrators correct supported exceptions and complete required approvals.
5. **Paycheck** uses the eligible recalculated hours, premiums, and deductions.

{% hint style="warning" %}
**important:** a time log proves that a punch was captured. it does not by itself prove that the time is approved or payable. review the assigned shift, day type, employee entitlement, required workflow, and recalculated payroll result together.
{% endhint %}

### trace an Hours result from source to payroll

an Hours result is built in layers. use the layer where the issue began instead of changing the final number first.

| layer            | sample source or control                                                                    | what it contributes                                                                                         | where to verify it                                                     |
| ---------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| capture          | **Desktop**, **Kiosk**, or **Mobile** clock in                                              | the employee's actual punch time and, when enabled, supporting photo or location context                    | **Hours → Timesheets**, the punch-level **Source**, and capture detail |
| direct entry     | employee-added (**EP**), manager-added (**MP**), or administrator-added (**Dashboard**) log | a punch or correction entered by a person rather than captured by a clocking channel                        | timesheet history, status, reason, approver, and source                |
| system entry     | **Autogenerated**                                                                           | a record created programmatically by a supported Ashima process                                             | timesheet history and the related workflow that created it             |
| bulk intake      | **Upload Manager → Hours**                                                                  | supported employee time records from the current import template                                            | row-level upload result, affected timesheet, and audit evidence        |
| schedule context | assigned shift, break rules, rest day, and holiday calendar                                 | the expected punches, scheduled hours, work date, and special-day classification used to interpret the logs | employee shift calendar and the **Work Schedule** shown in Hours       |
| company rules    | time-entry, tardiness, overtime, rest-day, holiday, and workflow settings                   | whether a log is accepted, how exceptions are measured, and whether work requires approval                  | the applicable Settings page and recalculated Hours result             |
| employee context | entitlement, approved leave, location, payroll group, and employment setup                  | whether a rule applies to this employee and whether scheduled time is covered                               | employee setup, leave record, and Hours detail                         |
| approval         | timesheet, overtime, rest-day, holiday, or mobile-clock-in request                          | whether captured or requested work is accepted for downstream use                                           | **Todo**, the application status, and approver history                 |
| payroll          | recalculated eligible hours and premiums                                                    | the time-based input used by an open pay run                                                                | employee pay details, payroll register, and relevant payroll report    |

{% hint style="success" %}
**tip:** follow the record from left to right: **capture → schedule → settings → employee context → approval → recalculation → report → payroll**. if the source punch is correct but the result is wrong, inspect the next governing layer before editing the punch.
{% endhint %}

\## choose the right evidence for a common question

| question                                            | start here                                                   | then compare with                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| where did this punch come from?                     | punch-level **Source** in **Hours → Timesheets**             | capture photo or location detail when enabled, plus timesheet history                          |
| why is the employee late, under time, or overbreak? | assigned shift and actual punches                            | **Tardiness Settings**, break rules, approved leave, and recalculation state                   |
| why is overtime lower than the time after shift?    | approved overtime record                                     | **Overtime Settings** grace, minimum, cap, pre-shift rule, entitlement, and actual logs        |
| why is rest-day or holiday work not payable yet?    | day classification and captured logs                         | required application, approval status, employee entitlement, and payroll rule                  |
| why does payroll differ from the timesheet?         | **Paid Hours Reconciliation Report** or employee pay details | source timesheet, approved applications, leave, pay-date scope, and open-payroll recalculation |
| who changed or generated the record?                | timesheet source and history                                 | **Log Summary** or the applicable audit trail when an administrator action must be traced      |

### understand the current Hours workspace

| workspace                          | use it for                                                                                               |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Timesheets**                     | review, add, edit, batch edit, soft-delete, recalculate, and export time logs                            |
| **Attendance**                     | review **Clocked In**, **No Show**, **Undertime**, and **Absent** conditions                             |
| **Punctuality**                    | review **Early Birds** and **Tardy** records                                                             |
| **Overtimes**                      | review employee overtime history, file overtime for an employee, export, or delete eligible applications |
| **Restday**                        | review work recorded on a scheduled rest day                                                             |
| **Reports → Hours**                | generate and review **Possible Errors**, **Attendance**, and **Paid Hours** reports                      |
| **Reports → Others → Log Summary** | trace dated administrator activity by administrator and module; it is not an employee punch report       |
| **Upload Manager → Hours**         | import supported time records in bulk and review row-level results                                       |
| **Todo**                           | approve or reject timesheet, overtime, rest-day, and holiday applications when workflow is required      |

### what should i review before changing a time record?

confirm the employee, shift date, assigned shift, required punches, captured source, leave context, pending applications, special-day classification, payroll state, and the downstream pay period. correct the shift first when the schedule is wrong. correct the timesheet when the punches are wrong.
