# manage administrator confidentiality rules

use **Rules** or **Admin Rules** to decide which employee populations an administrator can access. this setting is separate from the administrator's role permissions, company assignments, my team scope, and Workflow assignments.

**navigation:** **Control Center → Rules** for an owner, or **Control Center → Admin Rules** for a designated administrator

## choose the correct confidentiality population

use this table to choose the employee population the administrator needs.

| **Set Confidential** choice           | employee population the administrator may access |
| ------------------------------------- | ------------------------------------------------ |
| **Non-Confidential**                  | non-confidential employee records only           |
| **Confidential**                      | confidential employee records only               |
| **Confidential and Non-confidential** | both populations                                 |

a permission can allow an administrator to perform a function while this rule still limits which employee records are available. changing this rule does not give the administrator a new permission, company assignment, approval role, or my team scope.

## update one or more administrators

1. search for the intended administrator when needed.
2. select the checkbox for every administrator whose rule you intend to change.
3. choose the correct **Set Confidential** value for each selected row.
4. choose **Update Rules**.
5. complete the password confirmation.
6. review the success message and reopen or refresh the list to confirm the saved selection.

only selected rows are submitted. if **Update Disabled** appears, the update function has been disabled for the current environment; do not treat the visible dropdown as a saved change.

## verify or correct the result

confirm the administrator's saved rule and, when available, review the corresponding settings audit record. if the administrator still cannot see an employee, check company assignment, named-role permissions, account state, Admin My Team Access, Manager Privileges, and the employee's confidential status before broadening this rule.

> **warning:** **Confidential and Non-confidential** exposes the broadest employee population. grant it only when the administrator's work requires both groups.
