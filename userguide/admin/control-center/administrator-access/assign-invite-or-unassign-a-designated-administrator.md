# assign, invite, or unassign a designated administrator

## assign, invite, or unassign a designated administrator

use **Designated Admin** to assign an existing administrator or create and invite a new one. review the current designation and capacity before starting.

**navigation:** owner's **Control Center → Designated Admin**

### check the limits first

both assignment paths check the one-designated-administrator limit and subscription slots. a slot or designation error must be resolved before treating the assignment as complete.

> **important:** designation changes access beyond an ordinary named-role assignment. assigning an existing administrator sets designated status, changes confidentiality to **both**, and updates the associated access links.

### assign an existing administrator

choose the existing-administrator assignment path, identify the intended administrator, and complete the available assignment controls. check the result and the saved designation rather than relying only on the selection you made.

### create and invite a new administrator

use the new-administrator path and provide the required first name, last name, and an unused email address. middle name is optional. review validation and invitation feedback.

creation can succeed even when sending the invitation fails. check the saved administrator before assuming no account was created. use **Resend invitation** when available, complete its password prompt, and review the explicit success or error result. neither creation nor resend guarantees email delivery or account activation.

### unassign carefully

before unassigning, check any displayed active-workflow restriction and arrange the required workflow reassignment where that restriction applies. it is a conditional block, not an unconditional rule for every unassignment path.

after unassigning, review the administrator's role label, companies, permissions, and account state. correct any access that no longer matches the administrator's responsibilities.
