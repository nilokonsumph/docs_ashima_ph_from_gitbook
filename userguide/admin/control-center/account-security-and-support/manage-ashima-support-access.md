# manage Ashima Support Access

use **Support** to grant temporary account access when Ashima support needs to inspect or help resolve an issue. choose the smallest access level that supports the case, and disable access when the work is complete.

**navigation:** **Control Center → Support**

## understand the three controls

use this table to choose the support-access level required for the case.

| control                 | choice            | effect                                                                                                             |
| ----------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Support Access**      | **ON** or **OFF** | enables or disables support access for the payroll account. the other support choices are shown when access is on. |
| access type             | **read only**     | allows support to inspect the accessible account data without the full-access setting.                             |
| access type             | **full access**   | allows the broader support-access mode. use only when the support work requires it.                                |
| **Confidential Access** | **ON** or **OFF** | includes or excludes confidential employee information within the enabled support-access session.                  |

**Support Access** must be on before the access type or confidential choice should be treated as operational permission. **Confidential Access** does not create an independent support session.

## enable the required access

1. turn **Support Access** on.
2. choose **read only** unless the support case requires **full access**.
3. turn **Confidential Access** on only when the issue requires confidential employee information.
4. confirm each control remains in the intended state after the page refreshes.
5. tell the assigned support contact that the approved access is available through the support process used for the case.

each control saves when changed; there is no separate combined save action. changes are recorded in the settings audit trail.

## remove access after the case

1. return to **Control Center → Support**.
2. turn **Confidential Access** off when it is no longer required.
3. turn **Support Access** off.
4. refresh the page and confirm the master toggle remains off.

> **warning:** **full access** and **Confidential Access** can expose sensitive company or employee information. keep them enabled only for the approved support scope and duration.

## verify or correct the result

verify the visible controls and, when available, the support settings audit record. if a control does not persist, do not assume support has the requested access; retry after confirming the account context or escalate the failed save through the normal support channel.
