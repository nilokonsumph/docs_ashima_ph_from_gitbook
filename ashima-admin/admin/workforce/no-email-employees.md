# No-email employees

add an employee with no email or mobile number and set up login access

use this guide when an employee does not have an email address or mobile number, but still needs access to ashima.

in this setup, the employee does not use email or mobile as the username. instead, Ashima uses a fallback username based on the company key and the employee ID.

**navigation:**\
Go to **Workforce → select an employee → personal details → account information**

<figure><img src="../../.gitbook/assets/Screenshot 2026-04-30 at 5.30.03 PM.png" alt=""><figcaption></figcaption></figure>

## what is the difference between employees with email address and employees without them?

#### employee with email

* username is the email address
* admin sees **Send Password Recovery Email**

#### employee without email and without primary mobile number

* username falls back to `*{company key}-{employee id}`
* employee can use that fallback username on the employee portal

### quick workflow summary

| Situation                                     | What Ashima uses                                 |
| --------------------------------------------- | ------------------------------------------------ |
| Employee has email                            | Email becomes the main username                  |
| Employee has no email but has primary mobile  | Primary mobile number can act as the username    |
| Employee has neither email nor primary mobile | Fallback username `*{company key}-{employee id}` |

## what username does ashima use when the employee has no email or mobile number?

ashima checks the employee's login details in this order:

1. email address
2. primary mobile number
3. fallback username

if both email and primary mobile number are missing, ashima allows the employee to log in using:

`*{company key}-{employee id}`

Example:

`*one-3333`

{% hint style="info" %}
The primary username is either an email address or a mobile number.\
\
In the absence of both, the system will allow employees to login to ashima using an assigned "Company Key" plus the Employee's ID Number.
{% endhint %}

## when should you use this setup?

use this setup when:

* the employee does not have an email address yet
* the employee does not have a mobile number yet
* the company still needs the employee to log in to ashima

{% hint style="info" %}
do not use this setup if the employee already has a working email address or mobile number that should be used as the main username.
{% endhint %}

### <mark style="color:violet;">step 1: create or open the employee record in workforce</mark>

go to **Workforce** and open the employee record.

if the employee already exists, open:

* **personal**
* **account information**

this is where ashima shows the username currently assigned to the employee.

<figure><img src="../../.gitbook/assets/Screenshot 2026-04-30 at 5.23.05 PM.png" alt=""><figcaption></figcaption></figure>

### <mark style="color:violet;">step 2: check the username in account Information</mark>

in **account information**, review the following:

* **username**
* **mobile**
* **reset password**

if the employee has **no email** and **no mobile number**, which means the email address and mobile number fields in ashima are left blank, the system shows a fallback username in this format:

`*{company key}-{employee id}`

this confirms the employee is using the fallback login format instead of email or mobile login.

### <mark style="color:violet;">step 3: set a temporary password from the admin portal</mark>

in **Account Information**, click **Change** beside **Reset Password**.

ashima opens the password modal for employees who do not have an email address.

<figure><img src="../../.gitbook/assets/Screenshot 2026-04-30 at 5.23.20 PM.png" alt=""><figcaption></figcaption></figure>

#### what does the password pop up show?

The password pop up shows:

* employee name plus **Password Change**
* instruction text: `Copy the password generated and click save`
* **Password**
* **Random Password**
* **Save New Password**

#### how do you set the password?

1. click **Change**
2. click **Random Password**
3. copy the generated password
4. click **Save New Password**

After saving, Ashima shows a success message:

`Information successfully updated.`

### <mark style="color:violet;">step 4: give the employee the login details</mark>

Provide the employee with:

* the fallback username
* the temporary password
* the employee portal login page

Employee portal:

[https://ep.ashima.ph/login](https://ep.ashima.ph/login)

Example login details:

* **Username:** `*one-3333`
* **Password:** use the temporary password generated by the admin

### <mark style="color:violet;">step 5: employee logs in through the employee portal</mark>

On the employee portal login page ([https://ep.ashima.ph/login](https://ep.ashima.ph/login)), the employee enters:

* the fallback username
* the temporary password

### <mark style="color:violet;">step 6: employee is asked to create his new password.</mark>

once logged in successfully for the first time in ashima, the employee is prompted to create a new password

## admin checklist for no email employee

* Confirm the employee has no email and no primary mobile number
* Open **Workforce → Personal → Account Information**
* Confirm the fallback username is shown
* Click **Change**
* Click **Random Password**
* Click **Save New Password**
* Give the employee the fallback username and temporary password
* Ask the employee to sign in at [https://ep.ashima.ph/login](https://ep.ashima.ph/login)

###

## can a no email employee initiate a password change on his own?

yes. once logged in, the employee can choose to create a new password by following these steps:<br>

<figure><img src="../../.gitbook/assets/Screenshot 2026-05-04 at 16.46.18.png" alt=""><figcaption></figcaption></figure>

1. click the dropdown arrow beside his name on the top-right side of the page.
2. select **profile**.
3. go to **accounts**.

<figure><img src="../../.gitbook/assets/Screenshot 2026-05-04 at 16.46.58.png" alt=""><figcaption></figcaption></figure>

4. click **Edit**.
5. enter your current password.
6. enter your new password.
7. confirm your new password.
8. click **Save**.

## what happens if an email address is added to an employee who previously did not have one/no email employee?

once an email address is added, it becomes the employee’s username.

<figure><img src="../../.gitbook/assets/Screenshot 2026-05-04 at 16.19.13.png" alt=""><figcaption></figcaption></figure>

under Account Information, you will see that the username changes from the previous format (company code + ID) to the newly added email address.\
\
the employee can continue using their existing password to sign in.
